# Stage 9: Cleanup And Documentation

## Goal

Remove obsolete single-cube assumptions, update documentation, and leave the project in a coherent chess-game state.

## Cleanup Tasks

### Naming

Current names like `object0`, `cube`, and `ChessFetchTask-v0` can remain internally where compatibility requires, but public chess-game APIs should use:

- `piece`
- `square`
- `board`
- `game`
- `physical_move`

Do not rename everything at once if it risks breaking MuJoCo XML assumptions. Prioritize public interfaces and docs.

### object0 Removal Checklist

Before removing `object0` from XML, run this checklist:

1. `grep -r "object0" src/ tests/ scripts/` — list all references.
2. Confirm every reference has a chess-aware replacement (`active_piece_body_name`, `active_piece_joint_name`, or piece registry call).
3. Confirm `get_cube_position()` fallback path to `object0` is no longer reachable.
4. Remove `object0` body from `chess_env/assets/pick_and_place.xml`.
5. Run `pytest tests/ -v` — must pass.
6. Run `python scripts/verify_physics.py` — must pass.
7. Run `python scripts/eval_chess_reachability.py --all-squares --n-episodes 1` — must pass.

Do not remove `object0` if any test fails after removal. Investigate the reference, fix it, and re-run.

### Legacy Single-Cube Paths

After all chess scripts pass:

- Remove or clearly mark single-cube-only scripts.
- Keep legacy movement tests if they still protect the waypoint algorithm.
- Ensure `object0` is not the only supported active body.

### STL Asset Compliance

If any STL files were downloaded (not generated by `generate_chess_stls.py`):

1. Verify each asset has a permissive license (MIT, CC0, CC-BY, public domain).
2. Record license and source URL in `chess_env/stls/chess/LICENSES.md`.
3. Run `python scripts/verify_physics.py` with mesh loading to confirm triangle count < 2000 per mesh.
4. If a mesh is too large: simplify with `python -c "import open3d; ..."` or regenerate as a primitive.

If assets are generated by `generate_chess_stls.py`: no license concern; just verify the file is committed and the generator script is in the repo.

### Final State Agreement Check

Before declaring the refactor complete, run a single full-game agreement check:

```bash
python scripts/eval_chess_game_flow.py --moves e2e4,e7e5,g1f3,b8c6 --verify-agreement
```

With `--verify-agreement`, the script checks after EVERY move that:

1. `chess_service.fen()` matches expected FEN.
2. `logical_piece_tracker` square assignments agree with `chess_service.piece_at()` for all 64 squares.
3. `physical_occupancy` assignments agree with `logical_piece_tracker`.
4. Actual MuJoCo piece positions are within 5mm of `board_mapper.square_to_piece_xyz()` for all active pieces.

Any disagreement is a critical bug. The test must exit non-zero and print the specific discrepancy.

### Logs And Debugging

Add structured debug output for failed moves:

- FEN before move.
- UCI move attempted.
- Physical plan commands.
- Failed command.
- Stage result and crash reason.
- Active piece position.
- Grip position.

This output should be easy to paste into a bug report.

## Final Validation

Run the full validation workflow:

```bash
pytest tests/ -v
python scripts/verify_physics.py
python scripts/eval_chess_reachability.py --all-squares --n-episodes 1
python scripts/eval_chess_piece_move.py --piece white_pawn_e --src e2 --dst e4
python scripts/eval_chess_piece_move.py --piece white_pawn_d --src d2 --dst d4 --starting-position crowded
python scripts/eval_chess_game_flow.py --moves e2e4,e7e5,g1f3,b8c6
python scripts/eval_special_moves.py --all
```

Manual UI validation:

```bash
python scripts/run_chess_ui.py --host 127.0.0.1 --port 8000 --visualize
```

Verify:

- New game starts correctly.
- Human move works.
- Computer reply works.
- Illegal move displays an error.
- Let-computer-play works on current side.
- Special move cases can be demonstrated through scripts.

## Definition Of Done

The chess-game refactor is complete when:

- The simulator loads a colored chess table with all pieces.
- The table surface itself is the chess board.
- Chess square centers use exact 8cm cell geometry, not the movement sampling grid.
- Crowded starting-position moves do not displace neighboring pieces.
- Every legal move type has a tested physical plan.
- The arm moves board-to-board pieces using the existing waypoint algorithm.
- Graveyard and promotion reserve interactions use teleportation only.
- UI controls and monitors the game.
- Evaluation scripts cover chess-specific behavior.
- Documentation explains the architecture and operational workflow.
