## Overview

RoboChess is a MuJoCo-based simulation of a Fetch robotic arm playing chess on a physical board. The project is well-structured, with clear separation of concerns across five layers:

| Layer | Module | Purpose |
|-------|--------|---------|
| Simulation | `src/chess_env/` | MuJoCo physics, scripted controller |
| Chess Logic | `src/chess_game/` | Rules, move planning, engine |
| Physical Execution | `src/physical/` | Board ↔ arm coordination |
| UI | `src/ui/` | Flask web interface |
| Utilities | `src/utils/` | Config, logging, args |

## Key Strengths

1. **Clean layered architecture** — chess logic, physical execution, and simulation are fully decoupled.
2. **All tests pass** — comprehensive coverage from pure-unit through MuJoCo integration.
3. **Deterministic scripted controller** — 100% success on all valid board positions; errors ≤ 3.7mm.
4. **Full special-move support** — castling, en passant, promotion, all draw conditions.
5. **Robust grasp pipeline** — multi-phase plunge/close/hold/retract with cube-drop detection.
6. **Excellent config-driven design** — no magic numbers in source; physics and geometry fully configurable.

---

## Critical Findings (Requires Immediate Attention)

1. **`debug_one_move.py` ignores all CLI arguments** — the `--piece`, `--src`, `--dst` flags have no effect; the script is hardcoded to `e2→e3`. See `02_bugs.md` §1.
2. **`chess_env/__init__.py` contains broken legacy environment registrations** — `ChessFetch-v0` and `ChessFetchDense-v0` point to non-existent classes; instantiating them crashes. See `02_bugs.md` §2.
3. **`PromoteCommand` dataclass is unreachable dead code** — defined in `move_planner.py` but never generated by `MovePlanner.plan()` nor handled by `PhysicalPlanExecutor`; if somehow produced it silently causes a failure result. See `02_bugs.md` §3.
